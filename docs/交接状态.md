## 这是什么

飞书机器人接到本机一条已存在的 Claude Code 会话上。飞书里发需求 → 那条会话在它自己的仓库里干活 → 过程流式回到飞书卡片。全局只有一条活跃会话。

```powershell
conda activate oncall
python -m oncall_bot --config config.yaml
```

环境是 conda 的 `oncall`（Python 3.12）。`config.yaml` 不在库里（有 app_secret），模板是 `config.example.yaml`。

## 动手之前必须知道的几条

这些都是实测踩出来的，不看会重复踩：

| 结论 | 章节 |
|------|------|
| `receive_response()` 在长连接下会串轮。它只是「遇到第一个 `ResultMessage` 就 return」，后台任务的结果会被当成本轮答案。必须按 `origin` 关联，见 `runner/turn_stream.py` | 2.5 |
| `interrupt()` 之后连接不可复用，后续 `query()` 返回 `API Error: 422`。中断后必须丢弃连接重连 | 2.4 |
| 判断「本轮是否被中断」只能看自己记的 `abort_reason`，不能看 `terminal_reason`（中断后它是 `api_error` 而不是 `aborted_*`） | 2.4 |
| 二进制下载接口成功时 `resp.code` 是 `None`、`success()` 返回 `False`，必须看 `raw.status_code`。已抽成 `_binary_payload()` | 2.9 / 9.5 |
| 云文档正文要走 block 树渲染，`raw_content` 会丢图片位置（24 张图只给 23 个占位符） | 2.9 |
| 飞书卡片正文必须用 `markdown` 组件，`div`+`lark_md` 不渲染代码块和列表；标题 / 行内代码 / 表格两者都不支持，要做等价替换 | 8.5 / 9.6 |
| `<font>` 标签即使颜色名不被支持也会被静默吃掉，不能靠「标签没露出来」判断生效 | 8.5 |
| 本机走 DeepSeek 网关，SDK 报的 `total_cost_usd` 不可信，卡片不显示费用 | 2.6 |
| pydantic 默认不校验字段默认值，路径字段的 `~` 不会展开。两个 model 都加了 `validate_default=True` | — |

## 待办

**需要你在飞书后台/文档上操作的**

- 云文档里的图片下载不了：那篇文档的安全设置是「仅可编辑的人可复制、打印、下载」，机器人只有可阅读 → 403。要么把机器人提升为可编辑协作者，要么放宽该设置。应用权限本身是够的。

**代码层面可做的**

- 文件附件输入（`.md` / `.pdf` / `.docx`）。`im.v1.message_resource.aget` 已经在用了，图片那条链路改一下类型就行。
- ask 模式审批卡片：`can_use_tool` + `PermissionResultAllow/Deny` + `card.action.trigger` 回调，SDK 和飞书两侧的能力都已确认存在，回调通路也留好了（`app.on_card_action`）。
- 更多云文档类型：电子表格（`sheets.v3`）、多维表格（`bitable.v1`）、旧版文档（`drive.v1.export_task`）。
- B 模式：按 `chat_id` 多绑定并行。

## 主要风险

`permission_mode: bypassPermissions` 等于把本机 shell 交给白名单里的人，`runner.disallowed_tools` 是唯一兜底。`setting_sources` 含 `project` 会加载目标仓库的 `.claude/`。`policy.allowed_open_ids` 留空等于不限制。细节在 README 第 6 节。
