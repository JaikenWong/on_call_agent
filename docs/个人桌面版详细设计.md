## 1. 首版范围与默认行为

一台电脑、一个操作系统用户、一个专用飞书应用、一个已配对的飞书用户。可以登记多个项目和会话，任一时刻只接管一个会话，只执行一个 Claude 任务。产品入口是本人和机器人的私聊。桌面管理界面负责任务控制和诊断，飞书承载需求与结果。

| 交付 | 具体行为 |
|---|---|
| 接入 | 托盘常驻、配置自建机器人、本地确认配对、连接自检、断线重连。关窗口隐藏到托盘；“退出应用”才停止引擎。 |
| 会话 | 本地选择可信项目、新建或接管已有会话、明确释放给终端、列出已登记会话。最后一次绑定只是重启后的候选。 |
| 任务 | 文本、纯图片暂存、图文消息、可选云文档读取、进度卡片、排队、按任务取消、投递失败补发、重启后核对。 |
| 权限 | 默认按项目开放读取；修改需在桌面对该项目启用编辑策略。未配对、群聊、其他发送人均不能执行、列举或领取资料。 |
| 后续版本 | 群聊和共享话题、多设备、云执行器、多用户、多个并行写任务、终端实时双向接管、开机自启和自动升级。首版优先手动启动和签名安装包。 |

**用户可见的不变量**

1. 飞书显示“已排队”时，本机已有可恢复的任务记录。显示“完成”时，本机已有最终结果。
2. 一条任务从接受起就确定发送人、原消息、会话、项目与附件集合。切换页面、重试投递或重启均不得改变这五项。
3. 任务既有执行状态，也有投递状态。“Claude 已完成，飞书待补发”是合法且可操作的组合。
4. 无法确认前次 Claude 是否已经写文件时，停止自动推进，在任务详情提示核对工作树与会话历史。中断不会撤销已经产生的修改。

## 3. 桌面程序与引擎

采用 **PySide6 Widgets 桌面进程 + Python 引擎子进程 + 本地 SQLite**。界面和核心共用 Python 类型定义。Qt 事件循环留在 UI 进程，引擎继续使用 asyncio 和现有飞书 SDK 线程。桌面不暴露 HTTP 端口。界面关闭后，托盘和引擎继续工作。[Qt QProcess](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QProcess.html)

```text
托盘与窗口 ── QProcess / stdin、stdout ── 引擎（策略、命令、单写入器）
                                          ├── SQLite / 凭据存储
飞书私聊 ── WS 线程 ── 耐久接收 ──────────┤
                                          ├── 单 worker ── Claude CLI ── 授权项目
                                          └── 投递器 ── 飞书原消息 / 卡片
```

**生命周期。** GUI 拉起同包的引擎入口。引擎先获取 OS 用户级独占锁，再迁移 DB、恢复未完成任务、启动 IPC，最后在凭据可用时连飞书。第二次打开 GUI 唤醒已有窗口（同用户本地实例通知），独占锁失败的引擎立即退出。升级后的旧 CLI 入口也必须在接飞书或写会话前获取同一把锁；对于已经运行的旧版本或另一台使用相同 App ID 的电脑，在向导要求用户先停止旧桥。飞书对同应用的多个长连接随机投递，不能利用它实现本机主备。[飞书长连接说明](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)

**退出和崩溃。** GUI 正常退出先请求引擎停止接单、冻结队列、按任务中断运行项、落库并释放连接；10 秒未完成则结束自己启动的进程树，并按第 8 节恢复。引擎检测父管道 EOF 时走同一路径。用单独进程组管理本应用创建的 Claude 子进程，保存 PID、启动时间和实例标识；不得按进程名或过期 PID 杀用户的终端。引擎异常退出时托盘标红，最多重启 3 次并退避，之后显示诊断。登录后手动启动；睡眠时显示的“在线”以唤醒后的握手结果为准。

**模块落点（拟新增）。** `desktop/` 放托盘、窗口与 IPC 客户端；`engine/` 放入口、同用户实例锁、应用服务和协议；`storage/` 放 SQLite schema、事务和迁移。飞书与桌面调用同一应用服务；只在 `feishu/` 做飞书对象转换。引擎拥有 DB 写权限，UI 不直接改库或执行 CLI。旧 CLI 与桌面入口通过显式 profile 区分默认策略。

## 4. 用户操作与界面

### 4.1 首次启动与配对

1. **环境页。** 检查系统、可执行的 Claude CLI 绝对路径、版本、数据目录写入与钥匙串可用性。允许用户通过文件选择器指定 CLI；启动时直接传 argv。提示用户在终端完成自身凭据配置。单独的“试运行”按钮说明会发起一次实际模型请求，使用临时空项目，不接管私人历史。
2. **飞书页。** 输入 App ID/Secret，显示应用身份、连接状态与所需事件 `im.message.receive_v1`。基本收发与图片、云文档权限分开自检；图片需要消息资源权限，文档读取按实际启用的文档、知识库、素材能力授权。能力不足时只关闭对应功能。
3. **配对页。** 本机生成 128 位随机一次性挑战（5 分钟），用户从桌面复制 `/pair <挑战>` 到机器人私聊。引擎只接受可信应用/租户的人类私聊，常量时间校验挑战摘要；成功只创建候选并销毁挑战。桌面显示应用、租户、候选用户的 open_id 和聊天，让人在本机确认，确认前不能查询会话、下载或执行。每轮最多 5 次错误尝试，超限或过期重新生成。无挑战时静默忽略陌生消息。重新配对必须从桌面发起。
4. **项目页。** 本机选真实目录，预览规范化路径、项目名和工具策略。默认只读。选择“新建”或“接管已有”；后者提醒用户结束该会话的终端操作并确认。向导最后提供一次本人私聊 `/status` 检查，成功后显示“可以接单”。
5. **解绑。** 先停止接单，取消等待项，中断运行项并等待释放，撤销配对与所有可远程使用的授权，使旧目标的待投递记录失效。异常未核对时允许撤销授权，但继续保留本地核对记录。更换 App ID、租户或本人都要重新配对。

### 4.2 主窗口与托盘

| 页面 | 必须展示 | 能做的操作 |
|---|---|---|
| 总览 / 托盘 | 分别显示引擎、飞书、Claude 就绪状态，当前项目和会话，等待数；“电脑在线、会话待接管”与“可接单”分开 | 打开窗口、暂停接单、恢复、释放给终端、退出 |
| 项目与会话 | 项目别名、规范化目录、权限档位、会话标题和短 ID、接管状态 | 注册/撤销项目、在项目范围内查询本机历史、登记、接管、新建、释放 |
| 任务列表 / 详情 | 本地任务号、接收/开始/结束时间、原消息、绑定项目与会话、附件名、执行/投递双状态、结果与错误 | 停止目标任务、补发结果、打开项目、查看会话 ID、人工标记已核对 |
| 设置 / 诊断 | 脱敏应用和用户、CLI 路径和版本、可用能力、最后一次连接错误、队列及磁盘占用 | 更换凭据、重新配对、修改保留期、清理历史、导出脱敏诊断 |

暂停接单时拒绝新需求并说明原因，已接受的任务可继续。明确“退出”时提示运行项和队列将如何处理。窗口隐藏后必须能从菜单栏重新打开；托盘不可用时保留普通窗口。首版不做内嵌终端，任务详情提供路径、会话 ID 和可复制的续接提示，实际释放完成后才显示“可在终端继续”。

## 5. 收消息、路由与附件

### 5.1 身份、绑定和入口次序

`Principal = (app_id, tenant_key, sender_open_id)`；`Route = (principal, chat_id, thread_id 或空串)`。未配对时，应用身份以成功认证的专用 WS 连接和其配置的 App ID 为准；首个匹配挑战的事件只提出候选租户，租户与用户、聊天一同在本机确认后固定。每次接收检查事件应用身份、租户、`sender_type=user`、`chat_type=p2p` 和已配对私聊。字段缺失或来源不符时拒绝；先处理唯一例外的配对挑战。群消息即使来自本人并 @ 机器人也静默忽略。路由带 thread，附件和命令结果只在原路由使用。桌面首次接管时为配对私聊的默认路由建立绑定；遇到新的私聊子话题保持未绑定，提示回到默认私聊。机器人回复以原 `message_id` 和 `in_thread` 为准。

**入口顺序采用本机耐久接收顺序。** WS 回调只做有界解析、身份门禁、提交短事务，并在提交成功后返回。用 DB 写入器的有界队列与短 deadline（目标 1 秒，上限 2 秒）；满载/磁盘失败触发 SDK 失败应答并在 GUI 告警，具体应答须用锁定版本的 SDK 做故障注入验证。重复推送查到同一唯一键即返回成功。飞书要求约 3 秒内完成回调，模型执行、文件下载、网络校验与卡片发送均在事务外。SDK 的失败重推有边界；本机离线期间不能承诺消息全量补收。[飞书长连接说明](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)

飞书事件与桌面修改绑定的动作写入同一个有序输入表，单消费者按 `seq` 应用。任何涉及慢查询的操作在事务外准备候选，最终写入时校验 expected binding revision。任务接受的提交点是“应用该条输入”的事务；接受成功的回复在提交后发送。进程在输入提交后、应用前退出，重启仍能按序处理，旧授权失效则拒绝。网络层可能乱序；界面给每张图单独回执“已登记”，需严格关联时使用图文合发或等回执再发文字。

### 5.2 命令合同

| 私聊命令 | 桌面版语义 |
|---|---|
| `/help`、`/status` | 仅本人可用。返回当前路由的项目别名、接管/暂停状态、当前任务号与等待数，不回传全机路径和本机其他历史。 |
| `/sessions` | 列出桌面明确登记且获准远程使用的会话。序号映射绑定 principal、route 与授权版本，有效 5 分钟；过期要求重列。 |
| `/use <序号或ID>` | 所有输入形式都只能命中同一授权集合。已释放给终端的历史要求桌面重新确认接管。活动/等待任务未清时返回 BUSY 和任务号。 |
| `/new [项目别名]` | 仅在已授权项目建新历史。不接受远程任意路径；无别名沿用当前绑定项目。切换条件同 /use。 |
| `/stop [任务号]` | 给定 ID 仅停止本人、原路由的该任务；省略 ID 默认停止本路由的运行项，如无运行项且仅有一条等待项则取消该项，否则提示列出并指定。不会顺带清队列或 pending。 |
| `/pair <挑战>` | 仅在桌面开启配对窗口时有效。已配对设备不因收到新挑战而换人。 |

桌面批量取消须预览数量和目标，逐条写入终态并通知原消息。CLI 旧版 `/stop` 的全局语义保留在旧 profile；桌面帮助文本和测试独立维护。

### 5.3 截图和文档

- 纯图先按 `(route, binding_revision, message_id, ordinal)` 登记占位，后台下载。无绑定则拒绝并提示先接管。图文合发的图直接归当条需求。下一条普通文字只领取同路由、同版本、接收序在它之前、未过期且未领取的占位。
- 在同一写事务内完成容量检查、插入任务和附件认领。队列满时保留之前的图片。后收到的图片、迟到的下载、切换或释放前的暂存图均不能进入新任务。被领取但尚在下载的图最多等 30 秒；失败时在原消息说明缺失项并终止该任务，用户可明确发新需求。
- 沿用 10 分钟暂存、最多 9 张、单图 20 MiB 的初始值；下载并发 2，全局有界待下载数 18，超过上限明确拒收。按响应长度及实际读取字节双重限额，落临时文件后原子改名。首版数据缓存预算 1 GiB，超限清理已过期项后仍不足则拒绝新下载。需要用受限读取验证当前飞书 SDK 的二进制响应行为。
- 云文档默认关闭，仅本人私聊显式启用；用应用身份获取，界面解释其权限来源。模型只拿本任务准备的文件，每轮限定 `tasks/<task_uuid>/inputs`，不挂整个 inbox。保留现有链接解析与内容截断；已启用抓取时，显式引用的文档正文获取失败则在 query 前结束任务，列明缺失项；用户可去掉链接重新发送。可选的文内插图失败时保留正文并在卡片列出缺失插图。文件名由服务端生成，清理器只能删除产品数据根目录内的受管文件。[飞书云文档权限](https://open.feishu.cn/document/server-docs/docs/docs-overview?lang=zh-CN)

## 6. Claude 接管协议、权限与执行并发

**三个不同的对象。** `project_id` 表示本机登记的真实目录及其授权；`session_id` 是完整 Claude 历史 ID；`binding_revision` 表示一次桌面接管。短 ID 仅供显示。一个项目可有多条历史；同一份历史在本引擎中只有一个所有者。保存 `cwd` 的规范路径和目录身份（macOS 记录设备号与 inode），授权时和运行前均校验。目录移走、符号链接换目标、授权版本变化时停止，并要求重新登记。

| 接管状态 | 转移条件 | 行为 |
|---|---|---|
| released → acquiring | 本机用户明确接管，或私聊在已获桌面授权的候选范围内新建；无前序任务 | 先检查目录、历史归属、同一历史是否已占用；处理变更时禁止 worker 领取任务。 |
| acquiring → owned | 校验通过，旧连接已关闭，事务内写入新绑定版本 | 建立独占记录，失效旧序号和暂存图。首次 query 时才真正建连。失败回退为 released，提示恢复步骤。 |
| owned → owned | 热连接空闲、正常断开或被中断后重连 | 保留接管权，允许冷启动；空闲断开不能视为已交还终端。 |
| owned → releasing → released | 显式释放、切换、退出、撤销授权 | 停止接单；切换/手动释放遇到等待项或运行项返回 BUSY。用户先取消或等待。先收尾查询、断开连接，核验受管子进程已结束，再释放所有权并递增绑定版本。 |
| 任意 → needs_review | 异常退出、外部写入迹象、SDK 返回不匹配的 ID、旧 Claude 进程仍存活 | 禁止继续写入。展示会话与工作区，待用户核对并完成重新接管；旧进程不能确认已结束时仍禁止接管。 |

本机实例锁与接管记录只约束参与协议的程序。外部终端不会遵守本应用的锁。对已有会话，在桌面显示“先结束终端里的该会话，再接管”；记录最后一次已知历史位置或修改信息，冷启动时有异常变化就要求核对。该检测只能发现部分冲突。全新任务优先使用应用新建的历史。首版不将可见历史自动加入远程可用列表。[Anthropic 会话管理](https://code.claude.com/docs/en/agent-sdk/sessions)

**单 worker 的执行规则**

1. 单写入器用条件更新领取队首 `queued` 任务，标为 `preparing`。全机最多 1 条在准备/执行/停止，最多 5 条等待（含恢复冻结项）。附件下载和卡片投递各用独立有界队列。UI、飞书命令、空闲回收都不能直接关闭正被任务引用的 client。
2. 从任务快照重验 principal、绑定、目录身份和策略版本。检查图片、文档和首次运行卡片，建立此次工具许可。已有会话使用完整 ID 的 `resume` 与 `fork_session=False`；新建使用预分配 UUID 与 `session_id=`，存为 `pending_create`。首次中断/崩溃后先查询历史是否已落盘，再决定能否续接。
3. 热连接键包含完整会话 ID、工作区、策略版本、凭据配置版本、CLI 和有效 `add_dirs`。每个任务的输入目录不同时关闭旧连接重新创建。无附件无文档的同策略任务可复用。默认空闲 900 秒断开。项目设置、工具许可或凭据变化一律重新建连。
4. 在 `client.query` **之前**提交 `running` 及尝试标记。以 `TurnStream` 区分当前人类轮和后台任务结果。只在收到匹配的终态时落结果。若 SDK 返回不同的会话 ID，不改全局绑定；转入核对并展示预期和实际 ID。
5. 等待时间不计入执行超时。准备阶段分别限制下载（30 秒）和建连（60 秒）；运行阶段沿用 1800 秒总时长、300 秒无输出，均可从本地调整。取消与超时争用同一 CAS 与 interrupt 锁。运行中中断后读到终态再断开；10 秒宽限后收割受管进程树，未确认终态一律 `unknown`。后台子任务若可能继续写入，释放前需要一并确认退出。
6. 中断期间点击“释放”只能看到正在收尾，不能提前宣布可在终端打开。准备步骤每次 await 返回后、query 前再次检查取消标志；旧任务的回调只能更新自己的任务 ID 和版本。

**工具策略。** 桌面 profile 不沿用 CLI 的 `bypassPermissions`。第一档“查看项目”仅提供经过路径校验的读取、搜索工具；第二档“允许编辑”额外提供受限的项目内文件修改。首版两档均不开放任意 shell、子代理、MCP、网络工具和无人值守审批。若实现发现内置工具无法严格限制根目录，采用应用提供的范围受限工具，或在 OS 沙箱内执行；没有通过越界验收的档位不发布。可先交付只读试用，再开放编辑。

实施时将工具可用集合与授权判定分开：显式 `tools`/拒绝规则限制模型可见能力，路径敏感调用在每次执行前由可强制拒绝的入口核验（包含符号链接、创建文件的父目录和重命名目的地），并验证 hook 的拒绝优先级。不能用 `allowed_tools` 列表充当全部工具集合，或仅依赖 `can_use_tool` 捕获已经被规则放行的调用。关闭项目 hooks、MCP、插件与可扩大权限的设置源。仅单独注入所需认证和模型配置，不整体继承仓库或用户 settings；若现有用户依赖网关，提供本地凭据与端点配置，并在自检中验证。工作目录和 `add_dirs` 单独不足以形成 OS 沙箱。接管既有会话会携带旧历史；项目页显示这一点，用户需确认允许将该历史的输出发到本人私聊。生产编辑档以实际允许/拒绝矩阵验收。[Agent SDK 权限顺序](https://code.claude.com/docs/zh-CN/agent-sdk/permissions)

## 7. 数据模型与事务

macOS 数据根目录定为 `~/Library/Application Support/OnCallAgent/`。包含 `state.sqlite3`、`tasks/`、`staging/` 和版本化的非敏感设置。日志写 `~/Library/Logs/OnCallAgent/`。所有者私有目录/文件，SQLite 开启外键、WAL、可靠同步与短 busy timeout。写入串行化，事务内禁止 network await。磁盘写入错误返回失败，不能只打日志后继续执行。

| 表 | 核心字段与约束 |
|---|---|
| `profile` | 单行。应用/租户、配对 open_id 与 chat_id、授权代次、暂停标志、接管状态、当前 binding 引用；Secret 只存钥匙串引用。 |
| `projects` | id、alias UNIQUE、real_path UNIQUE、dir_identity、policy、policy_rev、revoked_at。 |
| `sessions` | 完整 session_id 主键、project_id、title、created_by_app、pending_create、remote_eligible、handoff_state、last_known_history。 |
| `bindings` | id、route_key、revision、session_id、project_id、授权代次、状态、起止时间。唯一 (route_key, revision)，只有一个当前 owned 绑定。 |
| `inputs` | seq 自增主键、source、app/tenant、source_id、auth_generation（接收时的授权代次）、route、principal、normalized_payload、received_at、applied_at、outcome。飞书 source_id 取 message_id；本地变更取 request UUID。唯一 (source, app, tenant, source_id)，唯一键各列均为 NOT NULL；本地来源填专用命名空间。T2 对比接收代次与当前代次，换人或撤销后拒绝旧输入。配对挑战只存校验结论与候选，不能存明文。 |
| `tasks` | 本地 UUID、display_no UNIQUE、input_seq UNIQUE、binding_id/revision、principal、reply_message_id、chat_id、thread_id、project_id、real_path/dir_identity、session_id、policy_rev、授权代次、prompt、exec_state、attempted_at、result/error、version 与各阶段时间。快照字段写后不可变。 |
| `attachments` | id、input_seq、ordinal、route、binding_revision、过期时间、状态、size、受管路径、claimed_task_id；唯一 (input_seq, ordinal)，同一附件最多属于一个任务。 |
| `deliveries` | id、input_seq、task_id 可空、target、kind、part_no、payload、state、card_id、attempts、next_retry、last_error；唯一 (input_seq, kind, part_no)，覆盖命令回执与任务卡片。 |
| `task_events` | seq 自增、task_id、from/to、reason、timestamp、instance_id；追加写入，用于恢复和脱敏诊断。 |
| `meta` | schema_version、profile_instance、clean_shutdown、last_engine_version、迁移标记与已处理的旧卡片引用。 |

对 `tasks(exec_state, input_seq)`、`inputs(applied_at, seq)` 与 `deliveries(state, next_retry)` 建索引。可用部分唯一索引约束“全库最多一条执行项”；应用仍需用条件更新核对受影响行数。用于 v1 schema 的约束示例：

```sql
CREATE UNIQUE INDEX one_execution_slot ON tasks ((1))
WHERE exec_state IN ('preparing', 'running', 'stopping');

CREATE UNIQUE INDEX one_owned_binding ON bindings ((1))
WHERE state = 'owned';
```

**四个必须原子的提交点**

- T1 接收。写 `inputs` 或命中去重约束，提交后才向飞书成功应答；此时仅代表本机收到。
- T2 接受。按序读取未处理输入，验证当前授权/绑定和队列容量；插入任务快照、领取附件、生成回执投递记录、标记输入已应用，一起提交。命令引起的状态变化同样与输入结果一起提交。重复应用只读取上次结果。
- T3 发起。仅从 `preparing` 转到 `running`，写 `attempted_at` 和 task_event 后才 query。这个标记意味着“可能已经调用”，即便执行器恰好死在调用前也按待核对处理。
- T4 收尾。写终态、结果、task_event 和最终投递记录，同一事务提交。飞书响应到来后只更新对应 delivery；final patch 返回 false 视为投递失败。卡片节流和最终定稿共享单卡片锁，迟到的 running 更新丢弃。

## 8. 任务状态、投递与恢复

| 执行状态 | 进入 | 允许离开 |
|---|---|---|
| queued | T2 已接受 | FIFO 领取到 preparing；取消到 cancelled；退出/恢复冻结到 held |
| held | 重启或正常退出冻结尚未发起的任务 | 本地用户核对并重新接管原会话后继续原任务，或取消 |
| preparing | 下载核验、创建运行卡片、建连，尚未 query | T3 到 running；取消到 cancelled；确定失败到 failed；重启到 held |
| running | 已提交调用意图 | 有匹配结果到 succeeded/failed；中断到 stopping；结果不明到 unknown |
| stopping | 中断请求已登记且可能有副作用 | 见到确认中断的结果到 cancelled；正常完成先到则按真实结果结束并说明取消来晚；超时/失联到 unknown |
| unknown | 已调用但未得可信终态或会话 ID 异常 | 桌面标记“已核对”，保留原始状态和备注。需要继续时新建任务，引用旧任务号，不重放旧 query。 |
| succeeded / failed / cancelled | 终态已持久化；失败记录所在阶段和已知副作用 | 仅补发终态、清理资料或新建关联任务 |

**held 恢复约束。** 快照不可改写。恢复时重新核验与快照相同的用户、项目、目录、策略、实际 session，以及旧进程已退出。若这次人工接管产生新 binding revision，显式记录 `task_events.resume_authorized`（旧/新版本、操作者、时间），只允许恢复此前未发起 query 的同目标任务。身份、授权代次或其他快照对象变化则只能取消原任务并重新提交。为避免 held 阻塞自身恢复，桌面的 task.resume_held 是普通接管 BUSY 检查的唯一特例：允许为同目标的 held 项恢复所有权，仍须确保没有运行项、没有其他目标的未决任务。恢复后返回 queued，并按原输入序排队。

**投递。** 状态为 `pending → sending → delivered`；可恢复错误进入 `retry_wait`，目标失效进入 `undeliverable`，发送结果不明进入 `delivery_unknown`。已知 card_id 的 patch 可以退避重试，采用 2/5/15/60 秒后转人工处理，限流响应优先尊重服务端重试时间。发送首卡前等待飞书确认并持久化 card_id；若确定失败，结束准备且不 query。若响应丢失，优先使用已验证接口支持的稳定幂等标识；仍无法判断时不重复创建卡片，桌面显示投递未知。长文本每个分片独立标记。补发时再次验证配对身份、应用、租户和原聊天；不自动改投新用户。

| 故障注入点 | 启动或恢复行为 |
|---|---|
| T1 前后进程退出 | 未提交依赖上游重推；已提交去重。旧的未应用输入在恢复模式按原序号处理，执行类输入进入 held 或提示重新接管，不能静默启动模型。 |
| 已排队、下载或连接中退出 | 尚无调用意图的任务冻结。下载临时文件可重新获取；卡片创建结果未知时按投递规则核对。 |
| query 已开始，电脑休眠/网络断开 | 飞书连接与 Claude 分别判断。模型可继续时照常本地落结果并延迟投递；连接失联且缺少终态时转 unknown。唤醒后先验身份和子进程，禁止自动重放。 |
| Claude 已改文件，结果尚未持久化 | unknown 阻止该会话继续领取。详情提供项目目录、任务号、时间、会话 ID 和“核对已产生的修改”。 |
| 已落结果，patch 失败或进程退出 | 仅恢复投递器。原任务的模型调用计数维持一次。 |
| 数据库损坏、迁移失败、磁盘写满、钥匙串锁定 | 停止新任务；记录脱敏诊断。不可读的 DB 保留原件，不自动创建空库接单。钥匙串解锁后才连接飞书；敏感结果不降级写入公共目录。 |

正常退出或崩溃后的默认接管状态均为 released 或 needs_review。恢复工作先校验上次实例的进程归属，再允许用户操作；外部进程状态无法证实时，保留核对入口。应用不承诺自动恢复离线期间飞书未交付的消息。

## 9. 桌面与引擎的接口

引擎把 stdout 专用于 UTF-8 JSON Lines，诊断走 stderr。每行一个对象，单条上限 256 KiB，按换行积攒再解码；任务列表分页，正文按页读取。两端都校验协议版本和字段。首帧是 hello（协议主版本、引擎版本、实例 ID），版本不兼容时显示修复提示并停止连接。GUI 使用 QProcess 的管道信号，不在 UI 线程同步等待子进程。一次取消请求的往返示例：

```json
{"v":1,"type":"request","id":"998fe502-e71e-49e1-a48c-d98b36adce3d","op":"task.cancel","params":{"task_no":42,"expected_version":3}}
```

```json
{"v":1,"type":"response","id":"998fe502-e71e-49e1-a48c-d98b36adce3d","ok":true,"data":{"task_no":42,"exec_state":"stopping","version":4}}
```

| 接口组 | 操作与返回约定 |
|---|---|
| 应用 | `app.snapshot` 返回主窗口所需状态和各实体版本；`app.pause`、`app.resume`、`app.shutdown` 控制接单与退出。 |
| 身份 | `setup.check` 查询分项自检；`pair.begin`、`pair.confirm`、`pair.revoke` 管理挑战、候选和授权代次。Secret 专用请求仅写钥匙串，不进入 inputs 或普通请求日志。 |
| 项目与会话 | `project.register`、`project.revoke`、`project.set_policy`；`session.list` 按项目分页；`session.new`、`session.acquire`、`session.release` 要求预期绑定版本。 |
| 任务 | `task.list`、`task.get`、`task.cancel`、`task.resume_held`、`task.mark_reviewed` 和 `delivery.retry`。人工核对只写备注，补发只唤醒投递器。 |
| 通知 | `engine.health`、`binding.changed`、`task.changed`、`delivery.changed` 均携带实例 ID、实例内递增序号和实体版本。通知可合并；序号有缺口或实例更换时重新获取 snapshot。 |

修改类请求以 UUID 去重，携带 expected_version。重复 ID、相同参数返回同一结果；同 ID 不同参数返回 `ID_CONFLICT`。超时后 UI 用原 ID 重试同一请求，直到知道命令是否被接受。配对挑战只驻内存，重启作废并重新发起。业务错误含 code、中文提示、涉及的任务号与可用操作。至少区分 `BUSY`、`STALE_VERSION`、`NOT_PAIRED`、`PROJECT_REVOKED`、`SESSION_NEEDS_REVIEW`、`QUEUE_FULL`、`STORAGE_UNAVAILABLE` 和 `DELIVERY_UNKNOWN`。飞书只使用适合原聊天的提示，详细路径与错误原因留在桌面。

## 10. 旧版迁移、数据保留和分发

**迁移。** 首次安装可选择导入原 CLI 的 YAML 和 JSON。按“预览 → 按项选择 → 提交”执行：可导入 App ID、有效 CLI 路径、资源限额和原会话作为候选；Secret 经验证写入系统钥匙串。旧白名单、无人值守工具权限、环境变量、pending 图片和当前会话所有权均须按桌面流程重新授权。旧 last_card 只有消息和聊天标识，无法证明原始应用、租户和本人；在本地显示“旧任务状态未知”，不自动修改飞书卡片。旧文件保留原样，提示其可能仍含明文凭据。以来源摘要记录完成标记，多次导入不重复建项目。DB 升级前在引擎独占锁内用 SQLite backup API 备份；升级失败保留原数据，旧二进制遇到更高版本拒绝写入。用户选择回退时提示备份时间及之后的变更。

**私密数据。** 默认保留任务正文与结果 7 天、已完成任务的图片和文档 24 小时、脱敏诊断 7 天；暂存图片另按第 5 节 TTL。未完成任务、未补发的结果和待核对任务不自动清理，列入占用统计。清理覆盖 inputs、deliveries、DB 备份等持有正文的副本；已处理输入保留最小去重键至少 30 天，超过该窗口的旧推送按事件时间拒绝执行。清理不操作工作仓库和 Claude 自身的会话文件。日志只写内部任务号、阶段、耗时和错误类别；默认去掉原文、截图片段、文档 token、绝对路径、环境变量和凭据。诊断导出前可预览。飞书密钥只由引擎使用，传给 Claude 的子进程环境按白名单构造。

**构建与安装。** 将 PySide6 设为 desktop 可选依赖。开发阶段使用源码启动 GUI 和 engine；macOS 发行阶段拟采用 PyInstaller 的目录式 app bundle，内含 GUI、可单独启动的引擎、Qt 平台插件及锁定依赖。用户选择自己已安装的 Claude CLI；打包检查显式排除 SDK 随附的 CLI 副本并验证实际 cli_path。发布记录固定 Python、Qt、SDK、SDK 支持的 CLI 版本范围、目标架构和最低实测系统版本。签名、公证、装订公证票据后在干净的 arm64 机器上从 Finder 安装启动，验收含空格/中文路径、钥匙串访问、托盘、退出及升级保留数据。引擎从 app bundle 定位，不能依赖开发机 shell 的 PATH。无发行签名时可供开发者源码验收，不能标记为可分发试用包。[PyInstaller 使用指南](https://pyinstaller.org/en/stable/usage.html)

| M1 无界面任务核心 | 实现 schema、迁移、单写入器、冻结与恢复；改写 runner 入口为任务快照；先接 FakeClaude/FakeFeishu | T1–T4 故障注入均通过，断电后不会重复执行，CLI 原有回归通过。 |
| M2 本人私聊跑通 | 串起配对、原消息去重、项目接管、原消息卡片、命令和附件领取；用临时本机配对入口调试 | 用两个账号分别私聊并从群里发送命令，只有已配对私聊可触发；真实测试仓库能完成并在终端续接。 |
| M3 可安装桌面试用 | 实现向导、托盘、项目/任务页、IPC、钥匙串、包内引擎和单实例 | 新用户从安装到首条只读任务无需编辑 YAML。关窗继续执行，退出后可安全回到终端。 |
| M4 发布验证 | 验证异常恢复、编辑策略、云文档可选项、旧数据迁移、日志导出、签名包升级 | 下表发布必测项通过，记录分项版本、观察结果与限制；未通过的可选能力隐藏入口。 |

**首个开发任务。** 用临时 SQLite 和两个假适配器跑通“本人私聊 → 任务快照 → 查询一次 → 结果落库 → 原消息回执”。在结果提交后主动终止引擎，再启动只补发卡片。这个切片可先验证并发、归属和恢复，再接真实 GUI 和模型。

## 12. 验收矩阵

自动测试使用临时目录、SQLite 文件、可控时钟和能够在指定阶段阻塞/失败的 SDK 与飞书适配器；断进程测试用子进程真正退出。每次统计 `query_count`、工具调用次数、原始回复目标和卡片 ID。以下编号可直接映射开发工单和验收记录。

| 编号 | 操作 | 预期与观测点 |
|---|---|---|
| A01 配对 | 挑战错误、过期、重复使用；候选未确认；其他人先发消息 | 无任务、下载或本机信息回复。成功配对一次；更换应用/用户后旧身份和旧投递全部失效。 |
| A02 用户与群隔离 | A 私聊发图，B 私聊发文字或 /stop；A 在群里 @ 发送 /sessions | B 与群均无执行/取消/会话列表；A 的下一条需求仍领到自己的图片。 |
| A03 数据归属 | 图片下载阻塞，随后送达文字；切换绑定后让下载完成 | 文字等待自己已领取的图片；晚完成的旧图不出现于新会话。队满也不清掉待领取图片。 |
| A04 排队与命令 | 短时间内送达 1 条运行、5 条等待和第 7 条请求；同时用桌面和飞书切换 | 上限固定，溢出有明确回执。等待项存在时切换返回 BUSY。被接受的任务始终在快照指定的项目中执行。 |
| A05 同会话续接 | 新建、运行、空闲断开后续问；模拟后台结果先于人类轮结果 | 完整会话 ID、历史和回答归属正确。空闲断开仍是 owned；显式释放后才允许终端续接。 |
| A06 停止竞态 | 建连前取消；运行中同时触发 /stop 与超时；结束时迟到一条进度更新 | 单任务最多一次 interrupt；建连前取消不 query；仅目标任务停止；最终卡片不会退回“处理中”。 |
| A07 重复与失败确认 | 同一消息并发送达两次，再注入 T1 提交成功但确认超时；另测磁盘写满 | 重推只建一项；写入失败不给成功应答；GUI 有告警。记录锁定 SDK 在真实推送中的重试表现。 |
| A08 执行断点 | T2 后、T3 后、真实/模拟工具修改后分别杀引擎 | T2 后冻结；T3 后转 unknown；核对前禁止续写。工具修改计数至多一次。 |
| A09 投递断点 | T4 后断网；patch 返回 false；首张卡创建成功但响应丢失 | 已成功的模型不重跑。已知卡可补发；首卡状态未知不再盲发。重启仍定位原任务与聊天。 |
| A10 项目权限 | 序号过期、猜完整 UUID、路径穿越、软链越界、目录替换、项目 hooks/MCP、只读档申请编辑 | 全部拒绝；观察越界文件、shell 与网络均无副作用。授权目录内的读/写分别符合所选档位。 |
| A11 所有权恢复 | 同时启动 GUI/CLI，重复点接管；模拟残留子进程；held 任务重新接管 | 单引擎单写者；旧进程不明时拒绝接管；held 只能明确授权原目标恢复；不结束用户终端进程。 |
| A12 桌面与分发 | 全新 macOS 账户安装，配置，隐藏窗口，睡眠唤醒，停网恢复，退出后重启 | 托盘状态反映实际连接；运行中断状态可查；没有孤儿执行器。用户数据目录独立于安装包。 |
| A13 迁移与隐私 | 重复导入旧配置，升级时中断，导出诊断并搜索植入的测试密钥/正文 | 无重复项目，无意外接管，无未授权写旧卡片。迁移可恢复；诊断、普通日志、IPC stdout 的日志转储均无秘密。 |
| A14 可选输入 | 启用云文档后模拟无授权、超大资源和下载超时；连续两个任务分别上传不同文件 | 明确说明缺失内容；工作目录只挂本任务输入；失败任务不借用另一任务的缓存。 |

发布记录分三份结果：离线回归与故障注入、真实自建飞书机器人与本人 CLI 的集成、干净 macOS 上的签名包验收。记录真实 SDK/CLI/系统版本及失败项。工程验收集中在“能否准确归属、能否安全停止、能否解释恢复结果”；个人试点另看用户是否能独立完成配对，并在下一次值班主动使用。
