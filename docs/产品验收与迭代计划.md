# 桌面版产品验收与迭代计划

本计划从 desktop-v0.1.1 的四平台发行开始，按“发布候选 → 审查 → 修复与补测 → 新版本验证与发布”循环推进。每轮产物包含提交、测试结果、设计差异和剩余验证事项。发行包的可启动性、任务流程的正确性和真实业务使用分别验收。

## 第一轮顺序

1. 完成 Windows x64、macOS arm64、macOS x64、Linux x64 的原生构建和成品启动检查，确认 Release 附件完整。
2. 逐条对照详细设计第 5–10 节和 A01–A14，记录已实现、存在差异、需要实机验证三种状态。优先检查消息权限、事务、取消、崩溃恢复、会话接管、附件领取和密钥。
3. 对实际入口做代码审查，用可复现测试固定问题，再修复。涉及已有安装的数据变更必须有迁移或向后兼容处理。
4. 用临时 HOME、模拟飞书及本地模型服务贯穿完整任务，覆盖新建、续接、编辑、图片、投递重试、中断与重启，确保不重复产生副作用。
5. 提交到开发分支，在 GitHub Actions 验证四平台，再创建新 patch tag 发布。检查归档内成品可运行、Release 附件与 SHA-256 清单一致。
6. 更新本计划的审查记录。重复处理未通过的发布门槛，记录后续需要用户账号和真实桌面环境验证的项目。

## 发布门槛

- 四个平台的测试、打包及归档成品启动检查全部通过。
- 已发现的高优先级可复现缺陷清零，关键设计差异有实现和测试。
- 同一输入只创建一个任务。执行成功后，补发与重启不再运行模型。
- 未配对用户、其他聊天、其他应用和群消息不能执行、读取或取消本人任务。
- 每条任务固定项目、历史和附件，切换、取消或晚到下载均不改变归属。
- 终端接管和任务执行不在本应用内部并发写同一会话。无法确认外部写入或执行终态时，要求核对。
- 密钥、正文和文档内容不进入普通日志或诊断包，退出后没有仍在写文件的受管执行进程。
- 数据升级保留既有安装的任务、配对和项目授权。失败恢复不以新空库掩盖原数据。
- 安装与操作文档与发行包一致，按平台明确系统要求、凭据服务、签名状态和使用限制。

## 真实环境验收

需要本人飞书账号、应用权限和模型凭据的联调由实际用户环境完成。待验证内容包括文档与图片权限、真实断网重推、模型长任务、系统休眠和解锁凭据存储。CI 和模拟验证完成后，可以称为已通过工程发布门槛；产品成熟还需真实值班使用记录、问题复盘及后续修复。
