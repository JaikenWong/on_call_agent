# Windows 个人桌面版

优先从仓库 Releases 下载版本对应的 Windows ZIP，解压后运行。推送形如 `desktop-v0.1.0` 的 tag 会自动完成测试、构建、冒烟检查并发布带 SHA-256 校验文件的试用 Release。

在仓库 Actions 的 **Windows desktop** 页面选择分支构建。推送到 `codex/personal-desktop` 或 `main` 会自动运行。成功后下载运行详情底部的 **OnCallAgent-Windows-x64** artifact，解开里面的 ZIP，保留整个 OnCallAgent 文件夹并运行 `OnCallAgent.exe`。同目录的 `OnCallEngine.exe` 与 `_internal` 是程序依赖。试用包未做 Windows 代码签名。

## 怎么用

### 开始之前（这两件事不在桌面里做）

**本机的 Claude Code。** 用当前 Windows 用户执行 `claude --version` 要能成功，并且已完成模型认证。桌面里要填的是原生 `claude.exe` 的**绝对路径**——保存时会校验它存在且可执行，相对路径或不可执行会被拒绝。

> **为什么要你自己装？** `claude-agent-sdk` 其实自带一份 CLI（`_bundled/claude.exe`，约 326 MB，版本锁定），而且 SDK 在没有显式指定 `cli_path` 时会**优先用自带的那份**。本产品反过来：打包时把 `_bundled/` 从产物里剥掉，强制你指定自己的 CLI。四个理由：
>
> - **认证绕不过去。** 自带 CLI 同样需要认证，登录态在 `~/.claude/`。捆绑省不掉「先装一次 Claude Code 并登录」这一步，只是把 326 MB 塞进安装包。
> - **产品前提本就要求。** 「接管已有历史」要求终端里已经有会话，这说明你本来就在用 Claude Code。
> - **版本一致性。** 自带的版本是锁死的，可能和你终端里的不一致，而两边读写**同一批会话文件**。用你自己的，等于和你在终端里看到的完全一致。
> - **分发条款。** 第三方产品捆绑 CLI 并借用 claude.ai 登录额度不被允许；用用户自己的安装与认证可以避开这个问题。

**飞书企业自建应用。** 开启机器人能力，事件订阅选「使用长连接接收事件」并订阅 `im.message.receive_v1`，把应用可用范围设成包含本人，然后**发布并等审核通过**。拿到 App ID 和 Secret。

### 首次设置（桌面「设置」页的 ①②③，必须按顺序）

界面上每一步右上角有状态标记（待填写 / 待配对 / 已连接 / 已配对 / 已接管），照着做完即可。

**① 接入飞书与本机 CLI** —— 填 App ID、Secret、Claude CLI 路径，点「保存并连接」。

- Secret 存进 Windows 凭据管理器，不写配置文件；留空表示沿用上次保存的
- 保存成功后引擎才会去建长连接：先取机器人身份（10 秒超时），再起长连接线程
- 卡片里的「长连接状态」和顶部状态条会实时反映结果：*未连接飞书* → *飞书长连接已建立* → 收到第一条消息后变 *飞书长连接正常*
- 「CLI 自检」会真的跑一次 `claude --version`，不确定路径时先点它
- 已经配对后又改 App ID 会被拒绝，要先解绑；只改 Secret 会让引擎自动重启

**② 配对本人身份** —— 点「生成配对命令」，复制那行 `/pair xxx`，在飞书里**私聊**机器人发出去，回到桌面点「确认配对身份」。

- 挑战码 **5 分钟**有效，而且「确认」这一步也受同一个期限约束，整个来回要在 5 分钟内走完
- 必须是私聊，**话题里发无效**（引擎直接丢弃带 thread 的消息）
- 挑战码是一次性的；连续输错 5 次会作废，要重新生成
- 发出去之后「候选」那一行会在一秒多后出现，确认后才写成「本人」

**③ 登记项目与会话** —— 去「会话」页，选项目目录。

- 「新建会话」= 在该目录下开一条全新会话
- 「接管已有历史」= 接管终端里**已经退出**的会话；没退出就接管会弄乱历史
- 登记时会问是否允许编辑，默认只读；之后可以用「设为只读 / 允许编辑」改
- 这两个操作都要求引擎当前空闲

### 日常使用

私聊发需求；也可以先发图再发文字，图会附在下一条需求上。可用 `/status`、`/sessions`、`/stop 任务号`。

执行状态和投递状态在「任务」页，选中一行就能看详情。任意时刻只接管一条会话、只跑一个任务；要换会话先「释放」。强制停止后若显示「结果未知」，先核对仓库和会话历史，再从桌面重新接管。

顶部的「暂停接单」可以临时不收新需求，已在跑的不受影响。

### 数据与退出

Windows 数据在 `%LOCALAPPDATA%\OnCallAgent`。关闭窗口只是隐藏到托盘，**托盘菜单里选「退出应用」才会停掉引擎**。托盘图标的右下角小圆点反映连接状态。

开发使用 Python 3.12，在虚拟环境运行 `python -m pip install -e ".[desktop,bundle,dev]"`。用 `oncall-desktop` 启动源码版，`python -m pytest -q` 运行回归。Actions 在 Windows x64 上测试，运行 PyInstaller 和 `packaging/check_bundle.py`，通过打包程序的 IPC 和 GUI 启动检查后上传 ZIP。自动测试使用临时数据目录；真实飞书和模型账号需单独联调。

## macOS 与 Linux

从 desktop-v0.1.1 开始，同一 tag 的 Desktop packages 流水线原生构建四种包，全部通过测试和成品启动检查后发布到同一个 Release。

| 平台 | 下载文件 | 启动 |
|---|---|---|
| Windows x64 | OnCallAgent-Windows-x64.zip | 解压，运行 OnCallAgent.exe |
| macOS Apple Silicon | OnCallAgent-macOS-arm64.zip | 解压，将 OnCallAgent.app 拖入“应用程序” |
| macOS Intel | OnCallAgent-macOS-x64.zip | 解压，将 OnCallAgent.app 拖入“应用程序” |
| Linux x64 | OnCallAgent-Linux-x64.tar.gz | 解压，运行 OnCallAgent/OnCallAgent |

macOS 两种架构分别在 macOS 15 runner 上验证，临时签名包尚未进行 Developer ID 签名和公证。首次打开可能需在系统“隐私与安全性”允许。macOS 数据目录为 ~/Library/Application Support/OnCallAgent，凭据使用系统钥匙串。

Linux 包在 Ubuntu 24.04 上构建，需图形桌面和 Secret Service 凭据服务。Ubuntu 可安装 gnome-keyring、libegl1、libopengl0、libxcb-cursor0、libxkbcommon-x11-0、libxcb-icccm4、libxcb-keysyms1、libxcb-xinerama0、libxcb-render-util0，并在已登录且钥匙环已解锁的桌面会话运行。数据目录为 ~/.oncall-desktop。Linux ARM64 发行包另行安排。
