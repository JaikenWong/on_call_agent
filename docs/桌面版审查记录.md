# desktop-v0.1.1 代码与设计对照

本轮以详细设计第 5–10 节及 A01–A14 为依据，通过实际消息入口、文件型 SQLite、可控子进程和临时模型端点审查。具体过程与发布门槛见产品验收与迭代计划。

## 已复现并修复

| 问题 | 用户影响 | 验证 |
|---|---|---|
| 只按数据库终态判断忙闲 | 子进程仍在收尾时会话可提前释放，配置也可能改变 | 活跃执行句柄持续到 finally 完成，释放和配置变更返回 BUSY |
| 清理后复用最高任务号 | 新任务可能重用旧任务的输入目录 | 单调任务号持久化，清理后新任务号大于原号 |
| 长结果只截取卡片前 5000 字 | 完整答复无法在飞书读取 | 原始结果落库并分片进入耐久投递表；重启不会重发已发送分片 |
| 历史查询异步返回时未复核绑定 | 较慢的历史导入可能覆盖较新的释放/绑定 | 写入前重验绑定版本和忙闲 |
| 取消等待项缺少原消息通知 | 飞书一直显示已排队 | 无卡片终态进入原消息投递表 |
| 图片格式识别的默认 PNG 回退 | 错误页可进入模型图片输入 | 下载内容需匹配受支持的图片魔数 |
| 普通回执只校验路由 | 相同用户解绑、重配后可能收到旧授权回执 | 回执持久化授权代次，投递时核验 |
| 冻结任务未复核编辑档位 | 项目降为只读后可能恢复旧编辑任务 | 恢复与执行时复核当前工具权限 |
| 进度卡片网络异常传播到模型执行 | 飞书更新失败会终止正在运行的查询 | 进度更新独立容错，最终结果继续落库 |
| 数据结构演进缺少可验证升级路径 | 老安装可能不能正确恢复投递 | v1→v2 保留配对、历史和任务，升级前 SQLite backup，补齐授权列 |

上述问题已有 tests/test_desktop_review.py 回归。scripts/check_desktop_claude.py 使用临时 HOME 与本地模拟模型服务，验证真实 Claude CLI 的读取工具、连续两轮会话及编辑工具实际写文件，避免把仅能启动误认为执行链路已经验证。

## 设计约定的覆盖与后续验证

| 范围 | 当前覆盖 | 验证边界 |
|---|---|---|
| A01–A04 配对、隔离、附件、排队 | 原入口测试、授权代次、附件单次领取、队满保留、满队列切换失败 | 飞书真实发送与平台重推需本人账号联调 |
| A05–A06 续接、中断、卡片竞争 | 原有流过滤与卡片测试，真实 CLI 续问、进程回收和持久终态 | Windows 强制中断按 unknown 处理；需要真实长任务验证时序 |
| A07–A09 耐久接收、执行和投递恢复 | SQLite 提交、去重、调用前 running 标记、冻结/unknown、已有卡片补发、长结果 outbox | 首卡返回未知时保守停止；未知发送分片保留 unknown，需核对 |
| A10 工具与目录权限 | 自有范围受限 MCP，默认读取，显式编辑，软链接/硬链接越界测试 | 权限依赖当前进程可控工具集合；外部本机程序由同一 OS 用户管理 |
| A11 所有权 | 单实例、单执行槽、显式接管与释放、暖连接键、残留进程检查 | 外部终端不参与本应用锁，需要用户确认结束同一会话 |
| A12 发行与桌面 | 四平台原生构建、打包引擎 IPC、Qt 界面启动与退出 | 发布签名、公证、各类真实桌面环境及系统休眠仍需验证 |
| A13 升级与隐私 | 升级备份、明文 Secret 不进入 DB、脱敏诊断、清理已结束资料 | 旧 CLI 配置导入采用预览后重新授权；升级备份由本机所有者管理 |
| A14 图片、文档 | 有界图片流、缓存预算、任务私有输入、文档失败终止准备 | 真实应用文档/图片权限和素材内容需本人账号联调 |

工程验收记录按平台和提交 SHA 绑定。真实值班可用性依赖实际账号、授权项目、模型与系统环境，须持续收集使用结果后再决定稳定版发布。
